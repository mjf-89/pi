# Pi Durable on Android — embedded Node proof of concept

A native Kotlin app embeds Node.js through **Javet 6.0.1**, runs the pinned Pi Durable
source, and stores a conversation in SQLite. It uses Pi's existing ChatGPT OAuth
implementation. No Termux, separate Node installation, or React Native is required
on the phone. Responses are generated by OpenAI, not by an on-device model.

## Install and try it

The debug APK for most current Android phones is
`app/build/outputs/apk/debug/app-arm64-v8a-debug.apk`.
The x86_64 APK is for compatible emulators/devices. Android 8.0 (API 26) or newer
and a 64-bit CPU are required.

1. Install the APK, allowing installation from the app you use to open it.
2. Open **Pi Durable**. The status should change from “Starting embedded Node…”
   to a Node version, SQLite, and the selected model.
3. Tap **Sign in with ChatGPT** and complete Pi's login in your system browser.
   Return to the app after the browser callback completes. A callback-URL paste
   fallback is available if needed. Never share that URL or your tokens in chat.
4. Send a message. If the selected model is unavailable to your account, use **Model**.
5. Force-stop and reopen the app. The conversation should reappear. Send another
   message to check that credentials survived the restart.

With ADB:

```sh
adb install -r app/build/outputs/apk/debug/app-arm64-v8a-debug.apk
adb shell am start -n dev.pi.android/.MainActivity
adb shell am force-stop dev.pi.android
adb shell am start -n dev.pi.android/.MainActivity
```

This is a debug build for development. Keep the same signing key when rebuilding
to install updates without uninstalling and losing app data.

If sign-in fails, tap **Export diagnostics** on the main screen or error dialog,
save the JSON file, and attach it to your report. Reproduce the failure before
exporting. Logs survive restarts and retain the latest 256 events, including the
installed version/commit, network state, DNS outcomes, OAuth stages and HTTP status.
Only allowlisted fields are stored: tokens, callback URLs, headers, response bodies,
device IDs and conversation text are excluded. Export uses Android's file picker.

## Build

Requires JDK 17 or 21, Node >=22.19, and Android SDK platform 35/build-tools 35.0.0.
The Gradle wrapper pins Gradle 8.13 and verifies its distribution checksum.

This project lives in the Pi repository's `android/` directory. Open that directory
in Android Studio. `pi-source.json` pins runtime source at commit
`a276dabe57911253350bffb93cb7d7aff6a73261`; the bundle script checks that Pi runtime
packages and root dependency files match that revision, while allowing Android-only
commits on top. It bundles Pi source and obtains only the generated model
catalog from the exact, lockfile-pinned `@earendil-works/pi-ai@1.0.0` npm package.
The Pi checkout does not need generated model data or a full monorepo build.

```sh
# From the repository root:
npm ci --ignore-scripts
cd android
npm ci --ignore-scripts
npm run bundle
npm run check
node --test test/*.test.mjs
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

Set `ANDROID_HOME` to your SDK, or create an ignored `local.properties` with
`sdk.dir=/absolute/path/to/your/sdk`. Android Studio can open this project directly;
Node must also be on the PATH of the Gradle process.

In the prepared cloud workspace, `source scripts/cloud-env.sh` selects the
installed JDK, SDK and writable caches before running the same commands.
`scripts/cloud-install.sh` refreshes and validates that prepared workspace. Other
machines should use the general build instructions above.

## What was checked

- Actual bundled Pi Durable: SQLite conversation storage and reopen, duplicate
  request IDs, OAuth state/PKCE/client-ID exchange, credential-event isolation,
  cancellation and retry. OAuth's token endpoint is mocked; the loopback HTTP
  callback server is real.
- The bundle also runs inside **Javet's Linux embedded Node 26.9.0**, with Java
  callbacks, a fake model response, SQLite and conversation restore. This checks
  the embedding bridge, separately from the host Node tests.
- Kotlin/Android APK compilation, TypeScript checking and Android lint.
- Diagnostic log privacy, bounded persistence, restart recovery, concurrent writes,
  and HTTP instrumentation preserving requests and response bodies.
- DNS bridging: actual HTTP fetch through the resolver bridge, IPv4/IPv6 ordering,
  resolver failure and cleanup, and HTTPS certificate/hostname verification.
  The Javet probe also exercises Java DNS callbacks and a real HTTP fetch.

The Android checks above pass. The broader repository's `npm run check` currently
fails at `packages/ai/test/stream.test.ts:705`: the Cloudflare fixture requests
`claude-sonnet-4-5`, while the repository-pinned catalog contains `claude-sonnet-4.5`.
This is an existing issue outside the Android project; the fixture is unchanged.

**Not yet verified:** execution on Android hardware, real ChatGPT subscription
login, streaming from OpenAI on Android, or Android process-death recovery while
a request is in flight. No Android device is attached to this cloud workspace.
Successful offline tests do not establish account eligibility or device compatibility.

`test/RuntimeProbe.java` and `test/embedded-smoke.cjs` contain the desktop Javet
probe. It needs the Maven artifacts `com.caoccao.javet:javet:6.0.1` and
`com.caoccao.javet:javet-node-linux-x86_64-i18n:6.0.1` on its classpath.

## Structure and current limits

- `runtime/index.ts`: provider, OAuth, durable harness, SQLite and command bridge.
- `runtime/credentials.ts`: serialized credential updates delegated to Kotlin.
- `runtime/android-dns.ts`: Node hostname lookup bridge to Android's system DNS.
- `app/src/main/java/dev/pi/android/`: UI, Javet worker, Android Keystore storage.
- `scripts/bundle.mjs`: reproducible source bundle; generated assets are ignored.

The Node runtime belongs to the Android Application and has a dedicated thread.
It keeps its callback server alive while the browser is foregrounded, provided
Android keeps the app process alive. There is no foreground service or guarantee
of continuous background execution. One conversation, text only, with no tools
or accessibility service is implemented in this POC.

OAuth credentials are encrypted with AES-GCM using a nonexportable Android
Keystore key; backups are disabled. Chat history is in app-private SQLite and is
not separately encrypted. Sign-out removes credentials but retains the chat.
Uninstalling or clearing app data removes both. Pi's original refresh logic is
retained, but real token refresh needs device validation.

The native runtime is comparatively large. APKs are split by ABI to avoid
shipping both native libraries to a phone. ARM64 ELF segments have 16 KB alignment.

Node hostname lookups use Android's `InetAddress` resolver on background workers.
Results return to the owning Javet thread before invoking JavaScript callbacks.
This routes lookups through Android's active network, VPN and Private DNS settings.
The affected phone still reports `ENOTFOUND`; exported diagnostics are needed to
identify where it fails. OAuth
exchange, refresh and API calls keep their original TLS hostname and certificate
verification; the app does not hardcode DNS servers or service IP addresses.
